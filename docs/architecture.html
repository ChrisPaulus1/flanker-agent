5 · What makes it safe to re-run

Cursor advances last

The event is stored before the version is recorded. A crash in between retries the release; the reverse would lose it forever.

Unique (app_id, version)

The database, not application logic, is what makes a duplicate event physically impossible.

Cache before spend

An existing (app, version) row short-circuits the run before the LLM is touched, so a re-view never pays twice.

Failures are isolated

One competitor failing is reported per-app and never aborts the run. Its cursor stays put for the next tick.
